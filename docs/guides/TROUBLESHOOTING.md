# Troubleshooting Nodaris

Start with non-mutating checks. Do not delete Registry files, vaults, backups, credentials, scheduled tasks, or tunnel configuration as a diagnostic shortcut.

## Local checks

From the checkout:

```powershell
node --version
corepack pnpm --version
git status --short --branch
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
```

Inspect the Agent and Gateway console output for their structured startup error codes. For the portable Windows runtime, run `scripts/windows/nodaris-portable.ps1 doctor` and `status` first. The MCP endpoint is `http://127.0.0.1:3333/mcp`; it requires the local Bearer token. The gateway does not expose `/healthz` or `/readyz`; those paths belong to the tunnel-client. Use the MCP `nodaris_health` tool for the Agent/Gateway health operation.

## Common symptoms

| Symptom                                            | Safe checks                                                                                                                                                                                                                                                             | Recovery direction                                                                                                                                                                                                                  |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Tool not found`                                   | Call MCP `tools/list` and record the exact server and tool inventory.                                                                                                                                                                                                   | Confirm ChatGPT is connected to the intended tunnel/workspace, then compare with the Gateway inventory. Restart only the correctly identified local process after reviewing its owner and configuration.                            |
| ChatGPT connects but Memory tools are absent       | Check the local feature mode, Registry association, capability, and server startup diagnostics without printing config values.                                                                                                                                          | Memory tools are conditional. Do not turn on global write flags or reuse another PC's IDs. Review the Memory V1 setup guide and stop if the installation-specific writer policy is missing.                                         |
| Agent health works but Gateway tool count is wrong | Compare Gateway `tools/list` with the ChatGPT-discovered list. Check that Agent and Gateway use the same version and environment mode.                                                                                                                                  | Use the supported supervisor only on the installation it was designed for. Avoid restarting a bridge alone when its parent runtime is stale.                                                                                        |
| Tunnel has no polling                              | Run `nodaris-portable.ps1 doctor`; when enabled, the portable profile is `%LOCALAPPDATA%\Nodaris\portable\tunnel-client.yaml`. Then run the official client `doctor --config <profile-path> --explain` and inspect its local UI/status while the supervisor is running. | Verify the operator's Platform organization/workspace association and runtime key. Do not publish or paste the key. Use `tunnel-disable` plus a separately approved runtime `stop` for rollback.                                    |
| MCP returns 401                                    | Verify the local Gateway token is provided via protected environment/file configuration and is the same for Agent and Gateway.                                                                                                                                          | Rotate a token only through a locally approved process. Never disable authentication to make the tunnel pass.                                                                                                                       |
| Project is missing                                 | Check `NODARIS_ALLOWED_ROOTS` and the machine-specific local project Registry.                                                                                                                                                                                          | Select/enroll one exact folder through the local TTY CLI. Do not add a parent disk or broad folder.                                                                                                                                 |
| Vault denied / `MEMORY_NOT_AUTHORIZED`             | Verify the local Registry `repositoryId`/`workspaceId` binding, vault identity, ACL and `memory.read` capability.                                                                                                                                                       | Keep the vault untouched until identity and policy match. Do not reenroll or change Registry permissions as a workaround.                                                                                                           |
| `INVALID_INPUT`, NTFS identity or ACL diagnostics  | Check the exact canonical path, volume, owner, DACL and reparse-point status using the documented preflight.                                                                                                                                                            | Fail closed. Do not elevate automatically, modify parent ACLs, follow junctions, or retry against a different path without a new local preview and approval.                                                                        |
| Reboot does not recover                            | Inspect the one intended Task Scheduler entry, its last result, `nodaris-portable.ps1 status`, and the sanitized tunnel-client health/status UI.                                                                                                                        | The `home-*` supervisor remains installation-specific. The portable task restarts the combined local supervisor a limited number of times; do not create a second task or tunnel. Preserve logs and use a controlled recovery plan. |
| Port conflict / duplicate process                  | Inspect listener PID, executable, start time, parent process and owner before stopping anything.                                                                                                                                                                        | Stop only a process proven to belong to this installation. Never terminate by image name alone.                                                                                                                                     |

## Recovery and evidence

Preserve the current working tree and local configuration. Capture only sanitized status codes, versions, and process identity metadata. A local health response does not prove tunnel polling or ChatGPT tool calls; validate each layer separately. If diagnosis requires an operational write, Registry change, service/task change, or tunnel reconfiguration, stop and obtain the operator's specific local approval first.
